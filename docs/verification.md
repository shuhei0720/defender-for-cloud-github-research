# 検証項目

対象は検証用のGitHubリポジトリ1件。既存の本番Workflowは変更しない。

| No. | 確認すること | 判定方法 |
| --- | --- | --- |
| 1 | GitHubコネクタがリポジトリを認識する | DfCのInventoryに表示される |
| 2 | GitHubの設定不備を検出する | 該当リポジトリがDfCの推奨事項に表示される |
| 3 | IaCの設定不備を検出する | テスト用Terraform/Bicepの検出結果、対象ファイルが確認できる |
| 4 | 既知の脆弱性があるOSS依存関係を検出する | Trivy由来の推奨事項にCVE、パッケージ、対象リポジトリが表示される |
| 5 | `uses:`のSHA固定Actionを認識する | SBOM / 推奨事項等でActionへの参照が確認できる |
| 6 | **固定したSHAに該当する既知CVEを検出する** | Action名・SHAと整合する脆弱性がDfCの推奨事項に表示される |
| 7 | 継続して検査される | スキャン日時が更新されることを確認する |

## SHA固定Actionのテスト

実在するGitHub Security Advisoryのうち、影響を受けるActionと修正リリース、対応するコミットSHAの関係を確認できるものを選ぶ。

検証専用リポジトリに、該当する古いSHAを使うWorkflowを置く。ただし実行しない。ソースコードの静的な取り込みと推奨事項を確認するための検証とし、権限・シークレットは与えない。

**Action名がSBOMに出るだけでは6番を合格にしない。** 影響範囲をSHAで判定できていることまで確認する。

## 記録項目

- 検証日、DfCコネクタ名、リージョン、対象GitHubリポジトリ
- 使用したスキャナー、既定ブランチ、スキャン日時
- テスト対象のGitHub Advisory、Action名、SHA、脆弱な範囲、修正バージョン
- 検出結果の名称、重大度、対象ファイル、CVE、DfC画面のリンク
- 未検出時の切り分け（スキャン未完了／依存関係を認識せず／CVE判定なし）

## 判定

1〜4が確認できれば、DfCによる一般的なリポジトリ検査には使える。

**6が確認できない場合、今回の主目的であるSHA固定Actionの脆弱性検知は未達。** DfCの標準機能で対応済みと扱わず、専用のチェック手段を追加検討する。
